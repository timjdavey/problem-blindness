# Reading the frameworks

These frameworks sort problems by what they are like, not by subject. Most split on one trait, such as how good the feedback is or whether the odds are known. A few, like wicked problems, bundle several traits under one label. The [frameworks index](index.md) lists them all by date, oldest first, so you can see which ideas grew out of which.

The [axes](../axes/README.md) are where the frameworks meet. Two frameworks that use different words for the same trait feed the same axis.

## What's on a framework page

Every framework page has the same parts, in this order.

| Part | What it holds |
|---|---|
| **Tagline** | The framework in one bold line |
| **Meta line** | The date, who made it, a link to the original and how many axes it feeds. A second year in brackets is the version most people cite |
| **The idea** | Where the idea came from and the trait it sorts problems on |
| **What goes wrong** | The mistake people make when they treat this kind of problem as another kind |
| **What to do instead** | The better response. Some pages fold this into What goes wrong when the framework names no clear fix |
| **Examples** | Two or three real cases, each under its own heading |
| **Axes** | A table of the axes this framework feeds, with each axis's group and what this framework adds to it |
| **Further reading** | The original source, plus free copies, explainers, books and critiques for anyone who wants more |

Every link under Further reading is also listed in the page's `sources` front matter.
